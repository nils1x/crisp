# Crisp

One native, signed macOS menu-bar app. Its menu has **Fast Space Switching**, a **Hyper Key** submenu (source key + **Hyper Key Settings…**), **Menu Bar Icon** (Supra or Rabbit), **Settings…** (⌘,) and **Quit Crisp** (⌘Q). Settings contains **Apps**, **Windows**, **Spaces**, and **Hyper Key**, reachable from the sidebar or with ⌘1–⌘4.

**If Crisp disappears from the menu bar.** Only one instance runs per login session; a second launch (including a rebuilt bundle that gets relaunched) activates the running copy instead of adding a competing item. Replacing `~/Applications/Crisp.app` while Crisp runs ends the old process cleanly, which looks like a quit. To tell that apart from a real fault, read `~/Library/Caches/com.nils.crisp/exit.log`: it holds a `clean exit` marker on normal termination, or the signal/exception backtrace when the process died on its own.

**Icons.** The app icon is the supra tile in `Resources/AppIcon.iconset`; `scripts/build-app.sh` turns it into `AppIcon.icns` and sets `CFBundleIconFile`. The menu bar glyph is the supra silhouette in `Resources/MenuBarSupra.png` (`@2x` for Retina), extracted from that icon by `python3 scripts/extract-menubar-icon.py`; the icon is white-on-white, so the script recovers the car from the pixels that are not the black tile, closes the outline and hardens the edges for 16pt. Choose **Menu Bar Icon → Rabbit** in the Crisp menu to switch back to the previous `hare.fill` symbol; the choice is stored in the config and applies immediately. No Hammerspoon, Space Rabbit, Karabiner, Raycast Hyper, yabai, or runtime shell-script dependency. SIP stays enabled. The old `init.lua` is retained for comparison but is not loaded by Crisp.

## Build and run

```sh
cd ~/dev/crisp
zsh scripts/build-app.sh  # runs tests; builds, signs, and verifies build/Crisp.app
# First install only (avoid overwriting a running app):
ditto build/Crisp.app ~/Applications/Crisp.app
open ~/Applications/Crisp.app
```

Crisp is installed at `~/Applications/Crisp.app`. Keep that path stable: macOS Accessibility/Input Monitoring grants and login items are tied to the app's code identity/path. Quit the installed app before replacing it with a new build. Do not run `swift run` for desktop testing; that executable is not the signed menu-bar bundle.

The app starts with instant Spaces **off** and Hyper **off** so it doesn't seize keys or remap Caps Lock until you choose to. Grant Crisp **Accessibility** and **Input Monitoring** in System Settings → Privacy & Security, then use **Request Permissions** in the Hyper tab and verify “Keyboard monitoring active.” Enable launch at login only after the features are tested.

- **Apps:** Option+G/R/M/F/O/Z/S focus or launch Ghostty, Reminders, Mail, Finder, Obsidian, Zed, and Search by bundle ID. If the app has a normal window, Crisp activates it; if all its windows are minimized, Crisp restores one. If the app has no window (for example, Safari after closing its last window with ⌘W), Crisp asks macOS to reopen it. Native switching to another Space follows the macOS “When switching to an application, switch to a Space with open windows” setting. Finder's no-window fallback opens the home folder. Edit/add/delete bindings in Settings. Click a shortcut field, press the actual key combination to record it, or press Esc to cancel; the physical keycode is saved. Bundle IDs use native `NSWorkspace`, not `~/dev/utils/focus-or-launch.sh`.
- **Layout dimensions:** X, Y, width, and height are normalized to 0–1 and use the system locale's decimal separator (comma on this Mac). Values are kept as a draft while the full rectangle is invalid, so adjust its position or size without a modal validation error; valid geometry saves immediately.
- **Spaces:** enable instant switching in Settings, then use Control+←/→ between adjacent native desktops. Crisp checks the active Space against the ordered display Space list before switching; first/last-edge presses are consumed without a transition. This boundary check and the synthesized Dock swipe use undocumented SkyLight/Dock interfaces and **must be tested on this Mac**; a macOS update could break them. If Crisp cannot read an unambiguous Space list, it suppresses the shortcut rather than risk macOS switching beyond an edge. macOS 27 uses a serialized HID payload and gesture envelope, without disabling SIP. Disable the toggle to use macOS's default animated switching. For the fastest possible animation-free Space changes (also for Dock and ⌘-Tab), turn off the Dock's slide: `defaults write com.apple.dock workspaces-auto-swoosh -bool true && killall Dock`.
- **Hyper:** select Caps Lock or F18/F19/F20. Crisp maps Caps Lock→F18 on connected keyboards and checks new/reconnected keyboards; an existing Caps Lock→F18 map is reused without claiming or deleting it. A conflicting Caps Lock map is left untouched and reported. With Caps Lock Hyper active, raw Caps Lock and key-down events are swallowed as a fallback, including if a conflicting remap turns the key into printable text; if a raw event locks Caps Lock, Crisp clears it outside the event tap. Test the actual key and indicator: software input filters cannot guarantee HID/LED behavior. Tap the Hyper source alone to do nothing; hold it for ⌃⌥⇧⌘. If Crisp crashes, macOS may retain a mapping created by that session; check before enabling another remapper.
- **Windows:** click the shortcut field to record a key combination, e.g. **Hyper + Delete** for Centered. Any number of layouts can share any shortcut; each separate press cycles eligible layouts in list order on the same focused window. Right Half and Right Third default to **Hyper + →**; use ↑/↓ beside the list to reorder the cycle. Cycling resets for a different window or shortcut and skips disabled/unavailable display sizes. Edit normalized x/y/width/height, add/remove layouts, and choose applicable display sizes. The previous saved Centered default is upgraded to Hyper + Delete if that key is free; custom shortcuts are preserved. Apps cannot share a shortcut with each other. On a collision, an enabled layout takes priority over apps and instant Spaces; an app takes priority over instant Spaces. Placement uses the focused window's visible display area; this is **not** yabai BSP, linked split resizing, or automatic tiling.

## Manual acceptance checks before retiring old tools

1. For every app binding, test shortcut behavior when the app is closed, has a normal window, has minimized windows, and is running without windows (for Safari: close the last window with ⌘W); verify focus, one-window restoration, and reopen. With macOS automatic app Space switching on, activate an app whose window is on another Space and verify macOS switches there. Also test a missing bundle ID and a target whose Accessibility window list is unavailable; verify errors/fallbacks without mistaking process activation for an opened window. Click an app shortcut field to record a new combination, then test it; verify Esc cancels and clicking elsewhere stops recording.
2. With two native desktops, toggle Spaces on and test Control+←/→ in both directions, including from the first/last desktop; toggle it off and confirm macOS's animation returns.
3. Select Caps Lock Hyper and verify a tap does not toggle Caps Lock or light the keyboard's indicator, holding it triggers a Hyper+layout shortcut, and Quit Crisp restores the original Caps Lock behavior. Test both internal and external keyboards and again after reconnecting the external keyboard.
4. Record Hyper + Delete for Centered if not already set; test the focused window. Press Hyper + → twice on the same window: Right Half, then Right Third; press it again to wrap back. Test reordering the layouts and changing windows. Test custom dimensions and a second display; verify a non-resizable/fullscreen window fails without moving unrelated windows.
5. Test Settings/Quit from the menu bar, quit/relaunch persistence, and launch-at-login after installing the signed app at its final path.

**Physical checks and reconnect regression:** an earlier installed build was physically verified on both the MX Keys Mini and internal keyboard, and Hyper + → cycled Right Half → Right Third → Right Half. Later the user reported Caps Lock Hyper intermittently stopped working and its light sometimes came on. A read-only probe found the current MX Keys Mini HID service unmapped while the two other services were mapped; after two watchdog intervals it was still unmapped. The old retained HID event-system client appeared to miss a replacement Bluetooth service. Crisp now creates a fresh service snapshot on refresh, tracks owned service registry IDs, and maps that previously missed MX Keys Mini service after relaunch. **The user physically confirmed the MX Keys Mini works as Hyper without lighting Caps Lock, including after turning the keyboard off and on.** Also unchecked: normal Quit cleanup, recording another shortcut, Hyper + Delete, reverse/edge Space switching, a second display, login-at-startup, and natural-scrolling changes. Read-only HID inspection cannot confirm a keypress or keyboard LED. Keep old helpers installed as rollback until these checks pass; they need not run.
